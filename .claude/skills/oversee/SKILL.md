# Oversee

You've been handed a set of GitHub issues. You have been given the mandate and ownership to ensure that these issues are
brought to completion. With this high level of trust comes a high level of responsibility, and you are the governing
authority. 

### 1. Ground yourself

First step is to prepare. Look over the issues, they should be well-defined, but they may contain outdated information
or assumptions that are no longer true. There may be multiple issues that share the same concerns, and thus should be 
merged into a single issue. Before you start assigning issues to workers, you must ensure that you have a crystal clear
vision of what is to be done and why. If any issues need to be updated or further refined it falls on you to do so.
If any more information from the human is needed, you must consult the human. 

### 2. Create the delegation plan
What issues can run in parallel? What issues block other issues? Create a concrete plan that you can follow
to ensure that workers are not stepping on each other's toes and the work ahead can go as smoothly as possible.

### 3. Begin delegating
Use /delegate for each issue, and common sense to orchestrate things properly.

### 4. Follow up
The /delegate skill already contains instructions for following up on each issue. But as overseer you will have many
balls in the air. So use the best of your abilities to ensure that each issue is brought to completion, with strong QA.
