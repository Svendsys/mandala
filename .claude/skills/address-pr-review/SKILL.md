# Address-pr-review

A review should have been performed on one or several of your pull requests, and now you must go over the comments
both inline and directly on the PR and address them.

### 1. Get the review comments
If no PR is mentioned, pick any of your open PRs and begin fetching all comments: inline, direct PR comments, and replies
to existing comments. Make sure you have all the data so that you do not end up missing anything.

### 2. Verify the review comments
Do not take any review comments as gospel. Whether it's a human, the repo maintainer, an AI agent, reviews contains 
mistakes and wrong assumptions. If a comment does not make sense, or if it appears to ask you to do something that
strays from the issue requirements, or from the project conventions or philosophies, or if you disagree for any reason,
then comment back on it and explain. There is nothing wrong about having a clarifying discussion.

### 3. Address reviews
After verifying comments, address the ones that you agree with using the same principles that you used when implementing
the issue. Then for each comment you address, reply to that comment with your solution and the corresponding commit. 

### 4. Wait for further feedback
When all comments have been addressed, wait for further instructions or new rounds of reviews.
